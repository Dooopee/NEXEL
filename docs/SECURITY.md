# Проверка загрузок и обновлений

[← На главную](../README.md) · [Установка](INSTALLATION.md) · [Поддержка](../SUPPORT.md)

## Источник файлов

Используй [выпуски Dooopee/NEXEL на GitHub](https://github.com/Dooopee/NEXEL/releases). Выбирай установщик, контрольные суммы и примечания **одного и того же выпуска**. Не подменяй контрольную сумму значением из другого сайта или другой версии.

## Встроенное обновление

При обновлении клиент использует подписанный манифест `nexel-update.json`. Проверка включает Ed25519-подпись, размер файла и SHA-256 установщика перед его запуском.

Эти проверки устанавливают соответствие обновления опубликованным данным и доверенному ключу клиента. Они не являются антивирусным анализом и не заменяют резервные копии игровых данных.

## Ручная проверка SHA-256

1. Скачай установщик и `SHA256SUMS.txt` со страницы одного выпуска.
2. В PowerShell вычисли хеш **скачанного установщика**. Ниже пример для файла версии 0.4.2; для другой версии подставь её фактический путь:

   ```powershell
   Get-FileHash -LiteralPath "$env:USERPROFILE\Downloads\NEXEL-0.4.2-windows-x64-setup.exe" -Algorithm SHA256
   ```

3. Сравни значение `Hash` с записью этого имени файла в `SHA256SUMS.txt`. Регистр букв не имеет значения; вся последовательность должна совпасть.
4. При несовпадении не запускай файл. Проверь, завершена ли загрузка и правильно ли выбран релиз. Если повторная загрузка из официального выпуска даёт тот же результат, сообщи о проблеме через [поддержку](../SUPPORT.md).

Если скачан ZIP, сравни хеш именно ZIP с записью ZIP. После распаковки установщик можно отдельно сравнить с записью EXE, если она приложена к выпуску.

SHA-256 помогает обнаружить несовпадение файла с опубликованной контрольной суммой. Сам по себе хеш не подтверждает безопасность программы или независимость источника контрольной суммы.

## Подпись Windows

Установщик пока не имеет Windows Authenticode-подписи. **Ed25519-подпись манифеста и подпись EXE в Windows — разные механизмы.** Не отключай защиту Windows для установки. Если происхождение файла вызывает сомнения, не запускай его.

## Отчёты о выпуске

Файлы релиза могут содержать `TEST_REPORT_RU.md`, `PUBLIC_DOWNLOAD_VERIFICATION.json`, `INSTALLATION_COMPATIBILITY_RU.md` и `SHA256SUMS.txt`. Состав зависит от версии. Отчёты описывают выполненные проверки и их ограничения, а не гарантируют отсутствие ошибок во всех окружениях.

## Конфиденциальные данные

Перед публикацией логов или снимков экрана удали пароли, токены, коды авторизации, личные email, адреса частных серверов и другие персональные сведения. Не загружай базы аккаунтов, зашифрованные хранилища или содержимое папок с личными мирами.

Если обнаружена возможная уязвимость, не публикуй рабочие секреты или подробности эксплуатации в открытом Issue. Начни с краткого обращения без чувствительных данных, чтобы согласовать подходящий способ передачи подробностей.
